# Аудит сетевых обращений офлайн-сборки

Исходная версия закреплена в manifest.json. Наша поставка использует изменённый
статический бинарник, а не неизменённый upstream release asset. Изменения доступны
в patches/offline.patch; SHA256 исходных/изменённых файлов — в
patches/source-files.json. Порядок пересборки: BUILD-OFFLINE.md.

## Изменения в исходниках

| Возможность upstream | Изменение офлайн-варианта |
| --- | --- |
| Обновление из GitHub | Реализация server-common/src/upgrade.rs удалена; команды возвращают локальную ошибку. |
| HTTP-прокси для плагинов | Обработчик server/src/handlers/proxy.rs возвращает 403; клиентский net.proxyFetch возвращает ошибку. |
| Удалённые HTTP-пространства | HTTP-клиент и операции в server-common/src/space/http.rs удалены; интерфейс возвращает локальную ошибку. |
| Внешняя авторизация OIDC | Обмен с провайдером в server/src/auth/oidc/client.rs удалён. Остаются локальные учётные записи. |
| Загрузка CIMD/JWKS для OAuth | Загрузчик server/src/auth/mcp/cimd.rs и DNS-resolver заменены локальными отказами. Локальная регистрация MCP-клиентов с PKCE сохраняется. |
| Загрузка моделей | HTTP-транспорт и тела загрузчика server-search/src/semantic/download.rs удалены; загрузка возвращает ошибку. |
| Git-синхронизация | Тело сетевого цикла удалено. Исполнитель принимает только локальные операции; transport-команды отвергаются до запуска Git. |
| Локальная Git-история | Новый ограниченный исполнитель: очищенное окружение, без hooks/filters/подписей/maintenance, запрет partial clone и alternate stores. Шесть типизированных MCP-инструментов работают через внутренний авторизованный router. |
| Серверный Chromium / runtime API | Фабрика возвращает отсутствие runtime; зависимость от Chrome runtime исключена. |
| Shell API | Обработчик возвращает 403 без запуска команды. |
| Сеть клиентского JavaScript | Проверка origin перед fetch/WebSocket/EventSource/XHR/beacon. Разрешены тот же origin и безопасные ресурсы в памяти. CSP ограничивает загрузчики ресурсов и переходы форм. |

Подробности локальных операций и границы коммитов/восстановления: MCP-GIT.md.
Восстановление проверяет текущую ревизию при записи, сохраняет предыдущую
контрольную точку и отвергает ссылки. Сетевые ограничения наследуются Git.

Отдельно исправлена передача пути пространства через X-Space-Path: сервер
кодирует UTF-8 путь в ASCII, клиент декодирует перед сравнением с config.
Это необходимо для TARGET с кириллицей, пробелами и знаком процента.

## Результат текущей сборки

Для binary_sha256/supply_revision из manifest.json выполнены проверка и
побайтное воспроизведение патча, сборка без доступа к сети, проверка статической
линковки и графа зависимостей. Новых версий зависимостей не добавлено.
Трассировка перечисленных ниже сценариев не выявила connect, UDP/raw-сокетов
или адресованных отправок у setup/server и всех их потоков/потомков.

Пройдены браузерные вход/чтение/правка/сохранение, OAuth PKCE, MCP чтение/запись/
правка/поиск, сохранность заметок после перезапуска и локальные отказы удалённым
операциям. Полный рабочий сценарий повторён при недоступном strace.
Проверены длинный TARGET с кириллицей, пробелами, %/$, 12 тестов установщика
и 4 проверки упаковки/подготовки релиза. Исходная ошибка Unicode-заголовка
воспроизводилась также с немодифицированным бинарником; исправленная версия
проходит тот же сценарий.

Локальный Git проверяется отдельными контрактными тестами под seccomp и полным
MCP-сценарием: история/diff/чтение, именованные коммиты, восстановление изменённой
и удалённой заметки, отказ устаревшей ревизии и ссылкам, недоступность .git и
сетевых команд. Трассировка охватывает дочерние процессы Git. Проверяется
сохранность истории после перезапуска и работа без установленного strace.

## Что проверять и фиксировать для каждого бинарника

- Целостность исходного архива и применённого патча; отсутствие новых версий
  зависимостей относительно проверенного lockfile либо отдельный их аудит.
- Граф **рабочих** зависимостей server binary: отсутствие reqwest, openidconnect,
  oauth2, chromiumoxide и hyper-rustls. Lockfile/лицензионный inventory содержат
  также необязательные пакеты workspace и не равны графу компоновки бинарника.
- Поиск реальных исходящих операций, DNS и запуска внешних команд в исходниках,
  включённых в сервер. Listen/accept/ответы клиенту и IPC не считать исходящими
  соединениями. Исходники тестов и исключённых workspace-компонентов учитывать
  отдельно от рабочей программы.
- Изолированный запуск под strace **на машине испытаний**: новая установка,
  запуск, браузерный вход/правка/сохранение, OAuth PKCE, MCP чтение/запись/правка/
  поиск, перезапуск, отказ внешнему HTTP-прокси/CIMD и командам upgrade.
- Проверка тех же рабочих функций при недоступном strace. В поставке и службах
  он не вызывается; устанавливать его на корпоративный сервер не требуется.
- Фактические Seccomp=2/NoNewPrivs=1 у server process, отрицательные проверки
  фильтра с EPERM и сетевой namespace с одним lo без внешних маршрутов.

Конкретный SHA256 бинарника и статус приёмки — в manifest.json. Сырые трассы,
параметры стенда, учётные записи и другие сведения машины не публикуются.
Изолированные тесты checkout находятся в tests/check_candidate.py,
tests/offline_runtime.py и tests/browser_workflow.py; браузерные зависимости
относятся только к машине испытаний.

## Граница утверждений

Отсутствие connect в трассе относится к выполненным сценариям этой сборки.
Аудит исходников и исключение транспортов дополняют динамическую проверку;
новый бинарник/патч требует повторной приёмки. Проверки на машине разработки
не являются приёмкой целевого сервера.

Seccomp, namespace, запрет ненужных функций и CSP сохраняются в готовой службе
как дополнительные ограничения. Без strace рабочая служба не ведёт журнал
попыток соединений. Наличие запрета не выдавать за измеренное отсутствие попыток.
Самостоятельные сетевые действия ОС или браузера пользователя не являются
сетевыми действиями кода SilverBullet и этим аудитом не охватываются.
