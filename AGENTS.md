# Работа с Second Brain

Перед сборкой или выпуском читать [RELEASING.md](RELEASING.md).
Каждый релиз обязан содержать две инструкции своей версии: INSTALL.md для
человека и agent.md для ИИ — внутри архива и отдельными файлами Release Assets.
Описание релиза начинается со ссылок на обе инструкции в теге этого релиза.
ИИ начинает установку с чтения agent.md в браузере.

Используется изменённое офлайн-ядро по OFFLINE-AUDIT.md/BUILD-OFFLINE.md.
Не заменять его официальным бинарником с сохранением статуса офлайн-приёмки.
Отсутствие попыток подтверждать аудитом исходников и локальной трассировкой
всех потоков/потомков; блокировку соединений не выдавать за отсутствие вызовов.
strace нужен только на машине испытаний и не входит в зависимости установки.

Перед установкой или управлением сервером читать [agent.md](agent.md).
TARGET всегда берётся из текущего поручения и передаётся аргументом.
Не подставлять путь разработки, путь другого проекта или каталог из примера.
В дистрибутив не включать сведения конкретной установки и данные тестового хоста.

Локальная история заметок описана в [MCP-GIT.md](MCP-GIT.md). Не добавлять
произвольный Git/shell MCP-инструмент или сетевые Git-операции. Коммит сохраняет
всё пространство; восстановление требует текущую ревизию и сохраняет историю.

Текущий профиль — обычные user-службы без namespaces/изменения capabilities.
Seccomp обязателен для ядра и Git; шлюзы имеют только фиксированные локальные
назначения. Прежний namespace-профиль не является текущим требованием.
Для исправления поддерживаемой установленной обвязки читать repair в INSTALL.md.

При запрошенном входе по IP:PORT использовать listen-host/public-url и
configure-plan/apply, а не обязательный SSH-туннель. Читать LAN-раздел INSTALL.md.
Обновление обвязки старого plain-service выпуска выполняется через repair.

## Доработка подключения агентов через SSH

В описании задачи зафиксируй три вещи: что происходит сейчас, что должен увидеть
пользователь после изменения и каким действием это проверить. Для подключения
сразу укажи клиент (OpenCode или GigaCode) и ОС рабочего места.

| Что меняется | Где искать код |
| --- | --- |
| Команда первого запуска, выдача файлов по SSH, обмен с SilverBullet | [ssh_mcp/bridge.py](ssh_mcp/bridge.py) работает на сервере. Режим `--prepare` готовит конфигурацию моста и печатает команды для сотрудников. |
| Загрузка и обновление клиента на ПК | [ssh_mcp/connect.py](ssh_mcp/connect.py) получает `client.py` через SSH, проверяет SHA256 из команды первого запуска и передаёт управление мастеру. |
| Вход, регистрация OpenCode/GigaCode, обычная MCP-сессия | В [ssh_mcp/client.py](ssh_mcp/client.py) режим `setup` настраивает выбранные приложения, а режим `mcp` запускается самим агентским клиентом при подключении. |
| Инструменты и инструкции выделенной роли | [agents/secondbrain.md](agents/secondbrain.md) содержит профиль OpenCode. Порядок настройки роли для обоих клиентов описан в [SECOND-BRAIN-SUBAGENT.md](SECOND-BRAIN-SUBAGENT.md). |

Серверные файлы моста размещай внутри каталога установленного проекта. Рабочая
копия клиента, профиль и личный токен сотрудника находятся в
`~/.silverbullet/ssh-mcp/` на его ПК. Сохраняй ограничение SSH-ключа фиксированной
командой моста. Список выдаваемых файлов задаётся мостом; пароль и токен остаются
за пределами аргументов команд, Git и диагностического вывода.

При изменении `connect.py` или `client.py` меняется SHA256 в строке подключения.
[tools/prepare_release.py](tools/prepare_release.py) формирует
`CONNECT-WINDOWS.txt` и `CONNECT-MAC-LINUX.txt` для имени `secondbrain`.
Для другого SSH-псевдонима администратор заново получает строку через
`bridge.py --prepare TARGET --ssh-alias ИМЯ`.

Для проверки логики клиента и моста запусти из корня репозитория
`python3 -I -B tests/test_ssh_mcp.py`. Для изменений первого запуска, SSH или
авторизации проверь полный путь командой `python3 -I -B tests/ssh_runtime.py`
на испытательной Linux-машине. Условия запуска и проверка с настоящим OpenCode
описаны в [RELEASING.md](RELEASING.md). В отчёте укажи, какие ОС и клиенты
проверены фактически. Если изменились действия сотрудника или администратора,
обнови [SSH-MCP.md](SSH-MCP.md) и [agent.md](agent.md) в той же правке.
