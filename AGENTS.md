# Работа с Second Brain

Перед сборкой или выпуском читать [RELEASING.md](RELEASING.md).
Каждый релиз обязан содержать две инструкции своей версии: INSTALL.md для
человека и agent.md для ИИ — внутри архива и отдельными файлами Release Assets.
Описание релиза начинается со ссылок на обе инструкции в теге этого релиза.
ИИ начинает установку с чтения agent.md в браузере.

Используется изменённое офлайн-ядро по OFFLINE-AUDIT.md/BUILD-OFFLINE.md.
Не заменять его официальным бинарником с сохранением статуса офлайн-приёмки.
Отсутствие попыток подтверждать аудитом исходников и локальной трассировкой
всех потоков/потомков; блокировку соединений не выдавать за отсутствие вызовов.
strace нужен только на машине испытаний и не входит в зависимости установки.

Перед установкой или управлением сервером читать [agent.md](agent.md).
TARGET всегда берётся из текущего поручения и передаётся аргументом.
Не подставлять путь разработки, путь другого проекта или каталог из примера.
В дистрибутив не включать сведения конкретной установки и данные тестового хоста.

Локальная история заметок описана в [MCP-GIT.md](MCP-GIT.md). Не добавлять
произвольный Git/shell MCP-инструмент или сетевые Git-операции. Коммит сохраняет
всё пространство; восстановление требует текущую ревизию и сохраняет историю.

Текущий профиль — обычные user-службы без namespaces/изменения capabilities.
Seccomp обязателен для ядра и Git; шлюзы имеют только фиксированные локальные
назначения. Прежний namespace-профиль не является текущим требованием.
Для исправления поддерживаемой установленной обвязки читать repair в INSTALL.md.

При запрошенном входе по IP:PORT использовать listen-host/public-url и
configure-plan/apply, а не обязательный SSH-туннель. Читать LAN-раздел INSTALL.md.
Обновление обвязки старого plain-service выпуска выполняется через repair.
