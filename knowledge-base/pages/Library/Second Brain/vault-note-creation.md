Адаптация `vault-note-creation` James Croft (MIT): [[Library/Second Brain/Происхождение]]. Перед записью прочитай [[Library/Second Brain/Правила]] и встроенный скилл `Markdown` через MCP `help`.

# Разобрать материал
1. Определи, что пользователь поручил сохранить: новую тему, практическую инструкцию, источник, проект или сведения о человеке. Прочитай предоставленный материал и существующие соглашения пространства.
2. Через `search` и `read` найди совпадающие и близкие записи, включая архив, если он есть. При точном совпадении обнови существующую страницу по [[Library/Second Brain/vault-note-update]], если это входит в поручение. Не создавай вторую страницу с синонимичным именем.
3. Выдели самостоятельные темы только там, где отдельная страница будет полезна. Описание понятия и длинную пошаговую инструкцию можно разделить и связать. Источник сохраняй отдельно от выводов, когда важно возвращаться к оригиналу.
4. Предложи краткий план, если требуется существенная реорганизация или объём создания выходит за исходное поручение. Обычную запрошенную запись не задерживай формальными согласованиями.

# Выбрать структуру
Используй существующий подходящий шаблон. Для новой базы есть начальные шаблоны:
* [[Library/Second Brain/Templates/Область]] — знания или ответственность.
* [[Library/Second Brain/Templates/Инструкция]] — действия с проверяемым результатом.
* [[Library/Second Brain/Templates/Источник]] — предоставленный материал и его происхождение.
* [[Library/Second Brain/Templates/Проект]] — цель, ход работы, решения.
* [[Library/Second Brain/Templates/Человек]] — только предоставленные рабочие сведения.

Это страницы-шаблоны SilverBullet, не текст для побайтного копирования. При работе через MCP прочитай шаблон, возьми тело после YAML, убери `|^|`, а YAML новой страницы возьми из поля `frontmatter`. Подставь фактическую дату вместо `${date.today()}`; не копируй служебные `meta/template/page`, `suggestedName` и `frontmatter` в запись. Через интерфейс человек может использовать `Page: From Template`.

Начальные поля: тип в `tags`, дата содержательного обновления `updated` в ISO `YYYY-MM-DD`. Добавляй `source`, `areas`, `status`, `owner` и другие поля только при наличии сведений. Сохраняй принятые в существующей базе имена и значения. Wiki-ссылки в YAML заключай в кавычки. Название страницы задаёт её имя: не добавляй YAML `name`.

# Записать и связать
1. Выбери понятное имя и путь. До записи проверь отсутствие страницы через `read`; при наличии перечитай её и пересмотри решение.
2. Напиши краткое описание, затем необходимые разделы. Не выдумывай даты, участников, ответственных, показатели или выводы источника. Пустые необязательные разделы можно убрать.
3. Проверь страницы-назначения ссылок. Используй полные пути, например `[[Areas/Сервис А]]`, а не `[[Сервис А]]`, если файл лежит в `Areas/`.
4. Создай страницу через `write` без `ifRevision`. Если её успел создать другой участник, прочитай результат и реши, нужна ли правка с текущей ревизией; не заменяй страницу автоматически.
5. Если поручение включает размещение в обзоре, добавь смысловую ссылку в существующий обзор через `edit` с актуальным `ifRevision`. Не создавай вручную обратные ссылки на каждой связанной странице.
6. Перечитай запись и изменённый обзор, проверь факты и ссылки. Сообщи имена созданных и обновлённых страниц и нерешённые вопросы.

Набор не требует веб-поиска, доступа к почте, журналам общения, shell, Runtime API, Obsidian Bases или Dataview. Содержимое вложения используй только если оно реально предоставлено и прочитано доступным способом; наличие PDF в базе не означает знание его текста.
