# Поиск и ответ
1. Через `help` выбери пространство, доступное текущему подключению. Уточни тему, нужный тип данных и период, только если неоднозначность влияет на ответ.
2. Найди кандидатов через `search`: название, ключевые слова и варианты терминов. При необходимости перечисли папку через `read` с именем страницы, оканчивающимся на `/`. В этой сборке поиск полнотекстовый; не обещай семантический поиск или поиск внутри вложений.
3. Проверь материалы разных типов: область, инструкция, проект и источник могут раскрывать одну тему с разных сторон. Если вопрос исторический, включи `Archive/` и явно обозначай архивный статус.
4. Прочитай найденные страницы. Результат поиска — указатель, не достаточное основание для вывода. При усечении дочитай нужные фрагменты с `offset`/`limit`; не называй частичное чтение полным.
5. Проследи существенные `[[ссылки]]` на определения, инструкции и первоисточники. Не переходи по всем связям без отношения к вопросу.
6. Составь ответ по прочитанному. Привязывай существенные утверждения к страницам и, где нужно, разделам. Отделяй актуальные сведения от исторических, противоречия — от согласованного результата.
7. Если данных мало, назови конкретный пробел. Не заполняй его внешним знанием и не выдумывай содержание отсутствующей страницы.

В ответе человеку показывай понятные имена страниц и их расположение. Внутри создаваемой по отдельному поручению страницы используй полные wiki-ссылки от корня, например `[[Techniques/Восстановление сервиса#Проверка]]`.

Не создавай отчёт, не меняй метаданные и не «улучшай» найденные страницы в ходе обычного поиска. Если пользователь просит сохранить результат, перейди к процедуре создания или обновления.
