Адаптация `vault-note-update` James Croft (MIT): [[Library/Second Brain/Происхождение]]. Перед записью прочитай [[Library/Second Brain/Правила]] и встроенный скилл `Markdown` через MCP `help`.

# Понять текущую запись
1. Найди целевую страницу через `search` или прочитай её по указанному имени. Если есть несколько существенно разных кандидатов и поручение не выбирает один, уточни цель.
2. Прочитай полный исходный текст и запомни `revision`. При усечении дочитай частями. Изучи разделы, теги, атрибуты и существенные связи. Шаблон — ориентир; не перестраивай существующую запись без причины.
3. Прочитай новый материал и связанные страницы. Различай новое знание, исправление ошибки, изменение текущего состояния и историческое событие.

# Подготовить правку
* Помещай сведения в подходящий раздел и сохраняй не затронутое поручением содержание.
* Текущее состояние обновляй с датой актуальности, когда она известна. События добавляй в хронологию. Не дописывай новое текущее состояние рядом с устаревшим так, будто оба одновременно верны.
* Исправляй доказанную ошибку в рамках поручения; для противоречащих источников сохраняй оба утверждения, ссылки и неопределённость. Не объявляй противоречие решённым самостоятельно.
* Сохраняй происхождение фактов. Личный вывод помечай как вывод. Не выдумывай сведения из почты, чатов, веба или непрочитанных вложений.
* Новую самостоятельную тему можно вынести в связанную страницу по [[Library/Second Brain/vault-note-creation]], если это входит в поручение. Не дроби запись ради формального соблюдения структуры.
* Проверь назначения новых ссылок. Используй полные пути от корня пространства; не добавляй вручную дубликаты обратных ссылок.
* Не перемещай запись из архива и не переименовывай её без отдельного решения: при перемещении нужно учитывать входящие ссылки.

# Применить и проверить
1. Для локальной правки используй `edit` с точными `oldText`/`newText` и `ifRevision` из обычного `read`. При необходимости предварительного просмотра используй `dryRun: true`.
2. Для обоснованной полной замены используй `write` с тем же `ifRevision` и полным актуальным текстом. Не собирай полную замену из усечённого предпросмотра.
3. При конфликте ревизий перечитай запись, сохрани чужую правку и заново подготовь изменение. Если изменения по смыслу несовместимы, сообщи о конфликте вместо обхода проверки.
4. Меняй `updated` только при содержательном изменении. Не приписывай себе, модели или другому человеку авторство через произвольные поля.
5. Перечитай результат, проверь сохранённые сведения, новые факты и ссылки. Если менялось несколько страниц, проверь каждую; MCP не обещает общей транзакции на все страницы. При частичном сбое сообщи, какие записи уже изменены.
6. Сообщи, что обновлено и почему, со ссылками на страницы; отдельно укажи противоречия и оставшиеся вопросы. Коммиты всей базы не делай автоматически: порядок снимков описан в [[Library/Second Brain/Правила]].
