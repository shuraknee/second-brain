# Правила ведения базы знаний через MCP

Краткая инструкция для пользователя: [как работают описания, где хранятся
скиллы и как их править](docs/KNOWLEDGE-USER-GUIDE.md).

Штатная схема — отдельный сабагент **secondbrain** по
[SECOND-BRAIN-SUBAGENT.md](SECOND-BRAIN-SUBAGENT.md). Правила и нужные процедуры
он загружает в собственный контекст; основной агент получает краткий результат
и ссылки. Описания навыков не нужно копировать в общий системный промпт.

Поставка содержит адаптацию трёх скиллов James Croft из
[obsidian-ai-second-brain](https://github.com/jamesmcroft/obsidian-ai-second-brain)
(MIT, фиксированная ревизия в `knowledge-base/manifest.json`).
Это инструкции для MCP SilverBullet: поиск, создание и обновление записей,
общие правила и пять шаблонов. Зависимости Obsidian, внешние коннекторы,
обязательный веб-поиск и shell-команды не используются.

## Новая установка

При первом запуске новой установки набор добавляется в созданное пространство:
`Library/Second Brain/`. Запуск существующего сервера не импортирует и не
перезаписывает инструкции автоматически. Новые пространства, созданные позже
через Dashboard, требуют отдельного импорта.

Данные обычных заметок автоматически не создаются и не реорганизуются.
Предложенные папки `Areas/`, `Techniques/`, `Resources/`, `Projects/`, `People/`
используются только как начальные соглашения для новой базы. Существующие
соглашения имеют приоритет.

## Добавить в уже установленное пространство

Обновлять бинарник, unit-файлы или конфигурацию старой установки не требуется.
Распакуйте проверенную новую поставку отдельно. SOURCE — её абсолютный каталог,
PYTHON — установленный Python >=3.9. SPACE_DIR — существующий абсолютный каталог
**заметок выбранного пространства**, не корень установки и не TARGET/data.
Посмотрите поле Folder в Space settings → General. Пустой `folder` в spaces.json
означает TARGET/data/spaces/<id>; относительный путь считается от TARGET/data.
Все значения берутся с целевого сервера, не из примеров или отчётов разработчика.

Сначала проверьте payload и получите список добавляемых страниц:

```sh
"$PYTHON" -I -B "$SOURCE/tools/verify_payload.py"
"$PYTHON" -I -B "$SOURCE/tools/knowledge.py" --space-dir "$SPACE_DIR"
```

`inspect` ничего не записывает. `pending` — отсутствующие страницы,
`unchanged` — уже совпадающие, `conflicts` — существующие отличающиеся страницы.
При конфликте `--apply` откажется от всего импорта до первой записи.
Не удаляйте и не заменяйте чужую инструкцию ради обхода: сначала сравните версии.

Для воспроизводимого операторского импорта выберите окно без редактирования
пространства. Собственные службы можно остановить штатной командой старой установки:

```sh
"$PYTHON" -I -B "$TARGET/tools/install.py" stop --target "$TARGET"
"$PYTHON" -I -B "$SOURCE/tools/knowledge.py" --space-dir "$SPACE_DIR" --apply
"$PYTHON" -I -B "$TARGET/tools/install.py" start --target "$TARGET"
```

Останавливайте только выбранную установку и только в рамках порученного импорта.
Импорт выполняется владельцем каталога, без sudo и сети. Символические ссылки
в пути/назначениях и hardlink-файлы отвергаются. Существующие отличающиеся файлы
никогда не перезаписываются; повторный импорт совпадающего набора безопасен.
Это не общая транзакция на все страницы: при ошибке записи JSON перечисляет
`created`, `pending` и `error`; сохраните отчёт, устраните причину и повторите
проверку. Уже созданные страницы удалять не требуется.

В работающем приложении внешне добавленные страницы индексируются наблюдателем;
при остановленном сервере — при следующем старте. В клиенте можно выполнить
`System: Reload`, чтобы обновить список шаблонов. Импорт файлов оператором
не является правкой от имени OAuth-пользователя; история может отметить его
как External. Он не заменяет журнал аудита действий агентов.

Если первый запуск прервался после создания users.json, изучите состояние,
проверьте наличие набора через `knowledge.py` и при необходимости завершите
его импорт явно. Сервер не перезаписывает инструкции при следующем старте.

## Использование OpenCode и GigaCode

Набор обнаруживается на стороне сервера по тегу `meta/skill`. Отдельная установка
скиллов в каждый клиент не нужна. Он не использует клиентские slash-команды,
поэтому процедура одинакова для OpenCode 1.19.5 и GigaCode 26.10.104 при условии
рабочего подключения к MCP. Проверка серверных инструментов не означает приёмку
закрытой корпоративной сборки GigaCode.

Первое поручение агенту:

> Через MCP second-brain вызови help и выбери пространство. Прочитай
> Library/Second Brain/Правила, затем подходящий скилл:
> vault-knowledge-retrieval, vault-note-creation или vault-note-update.
> Перед записью прочитай также встроенный Markdown. Используй эти процедуры
> для текущего поручения, сохраняя действующие соглашения базы.

Примеры вызовов **инструмента MCP**, не shell-команды:

```json
{"space": "Имя пространства", "topic": "Library/Second Brain/Правила"}
```

```json
{"space": "Имя пространства", "topic": "Library/Second Brain/vault-note-creation"}
```

`help` выдаёт доступные скиллы и их описания, но не загружает все инструкции
автоматически и не блокирует запись без их чтения. Для устойчивого выбора
укажите приведённое правило в постоянных инструкциях клиента вашей организации.
Не копируйте весь набор в каждое поручение: агент читает нужную процедуру через MCP.

Шаблоны доступны человеку через `Page: From Template`. Агент читает их как
страницы и составляет обычный Markdown: служебный YAML шаблона, `|^|` и выражения
даты не должны попасть в готовую запись. Шаблоны не устанавливают Lua или CSS.

## Проверка

Через `help` должны обнаруживаться четыре скилла из `Library/Second Brain/`:
общие правила и три процедуры. Прочитайте каждый, затем создайте отдельную
тестовую запись, проверьте её ссылку на существующую страницу и обновите её
с текущим `ifRevision`. Устаревшая ревизия должна быть отвергнута.
Проверьте историю и сохранность инструкций после перезапуска.

Инструкции не добавляют роль «только данные», защиту Library от редакторов,
серверную проверку заполнения всех полей или подробный журнал каждого агента.
Это отдельные функции, не свойства текста скилла. Веса и локальные модели
не нужны для импорта; их качество этим испытанием не оценивается.
