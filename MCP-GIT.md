# Локальная история заметок через Git и MCP

Каждое пространство хранит собственную Git-историю рядом с заметками.
Она позволяет сравнить версии, найти автора/коммит, сделать контрольную точку
и восстановить файл. История остаётся на сервере; к публичному репозиторию
установщика она не подключается. Remote не создаётся. Push, pull, fetch, clone,
SSH, произвольные команды Git и shell через эти инструменты недоступны.
История на том же диске не заменяет резервное копирование.

## Режимы установки

`install.py plan --history-mode managed` — значение по умолчанию: для нового
пространства создаётся локальный репозиторий, включены автоматические снимки и
именованные коммиты. Это контрольные точки, а не запись каждого нажатия клавиши.
Нужен заранее установленный системный Git >=2.34. Программа его не скачивает.

`--history-mode unmanaged` позволяет просматривать заранее подготовленную
локальную историю; автоматические и именованные коммиты/восстановление выключены.
`--history-mode disabled` отключает историю и требование Git. Установщик создаёт
только новую установку; эти параметры не являются миграцией существующих данных.

## Инструменты агента

Сначала вызвать `help` и получить доступное имя пространства. Для истории нужен
авторизованный пользователь с правом записи в это пространство. Каждый `path`
относителен пространству и включает расширение файла, например `Проект.md`.

| Инструмент | Аргументы кроме обязательного `space` | Действие |
| --- | --- | --- |
| `git_status` | — | Режим истории, последний коммит, несохранённые изменения. |
| `git_history` | `path?`, `limit?` (1–200), `before?` | История пространства или файла; `before` — полный id коммита для следующей страницы. |
| `git_diff` | `path`, `fromRevision?`, `toRevision?` | Без ревизий — HEAD против текущего файла. С `fromRevision` — коммит против `WORKING` (по умолчанию), `HEAD` или другого коммита. |
| `git_read` | `path`, `revision` | Версия из полного id коммита либо `WORKING`; возвращает содержимое и его ревизию. |
| `git_commit` | `message` | Именованный снимок **всех** ожидающих изменений пространства. |
| `git_restore` | `path`, `revision`, `ifRevision` | Контрольная точка перед восстановлением обычного файла из коммита как новой правки. |

Git id коммита — 40 шестнадцатеричных символов из `git_history`/`git_commit`.
`ifRevision` — другое значение: точная текущая ревизия содержимого из обычного
`read` или `git_read` с `revision: "WORKING"`. Сохранять кавычки в значении
`"sha256:…"`. Для отсутствующего файла явно передавать `"missing"`.
При несовпадении перечитать файл, оценить чужие изменения и повторить решение.
Защита проверяется также при самой записи, поэтому промежуточная правка не
перезаписывается вслепую.

## Порядок работы

1. Посмотреть `git_status` и при необходимости `git_diff`/`git_history`.
2. Перед большой правкой сделать `git_commit` с понятным сообщением. Учесть,
   что снимок включает также ожидающие правки человека и других агентов;
   отдельного коммита выбранных файлов здесь нет.
3. Читать и менять заметки обычными `read`/`edit`/`write` с актуальным
   `ifRevision`. Проверить результат и сделать итоговый `git_commit`.
4. Для восстановления сначала прочитать нужную старую версию и текущий файл.
   Вызвать `git_restore`, передав старый Git id и текущую ревизию содержимого.
   Проверить результат; при необходимости дать ему отдельный именованный коммит.

Восстановление сохраняет прошлые коммиты и остальные файлы. Оно не делает reset
всего пространства. Ссылки, включая hardlink, и исторические symlink отвергаются.
Восстанавливаемый файл ограничен 16 MiB. Чтение/diff возвращают предпросмотр
до 128 KiB; учитывать `truncated`, `encoding` и `bytes`. Усечённое содержимое
нельзя использовать как полную замену файла.

## Ограничения исполнения

Git запускается только для разрешённых локальных операций с очищенным окружением.
Глобальные/системные конфиги, hooks, фильтры, external diff/textconv, fsmonitor,
подписи, автоматические maintenance и ленивое получение объектов отключены.
Неизвестные настройки репозитория, partial clone, shared/alternate object stores
и ссылки на metadata отвергаются. Старые remote-настройки допустимы только как
неисполняемые метаданные; транспортные команды запрещены до запуска Git.
Репозиторий родительского каталога не используется вместо истории пространства.

Git наследует тот же seccomp-запрет исходящих соединений, что сервер.
Namespaces для запуска не используются. Проверки
кода и сценариев, включая его дочерние процессы, описаны в OFFLINE-AUDIT.md.
Ветки, слияния и сетевую синхронизацию MCP-интерфейс этой поставки не предлагает.
