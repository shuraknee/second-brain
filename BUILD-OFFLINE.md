# Сборка офлайн-варианта SilverBullet

Это инструкция для машины сборки. Для установки готового продукта использовать
INSTALL.md или agent.md; Node.js, Rust, компилятор C, Chromium и strace
на целевом сервере не требуются. Для локальной истории нужен установленный
системный Git >=2.34; с `--history-mode disabled` он не нужен.

## Подготовленные входные данные

1. Зафиксированный архив upstream из `source_url` в manifest.json. Проверить
   его `source_sha256`, распаковать в отдельный новый каталог SOURCE.
2. Checkout обвязки выбранного тега; `patches/offline.patch` и
   `patches/source-files.json` из этого же checkout.
3. Подготовленные зависимости Cargo.lock/package-lock.json, включая источники
   Git-зависимостей. Загрузки выполняются заранее разрешённым способом.
   `cargo vendor --locked --versioned-dirs` и `npm ci --ignore-scripts`
   относятся к подготовке зависимостей, не к установке приложения.
4. Rust/Cargo 1.99.1 и стандартная библиотека x86_64-unknown-linux-musl,
   Node.js 24.22.2 / npm 11.19.1, GCC и musl-инструментарий. Исходная проверка
   использует musl 1.2.4. Точные источники/параметры новой пересборки фиксировать
   отдельно, без сведений о сервере. Изменение инструментария требует проверки
   совместимости, состава библиотек и их лицензий.

Все пути задаёт собирающий. SOURCE, CARGO_HOME, каталог vendor, компилятор C
и каталог результата могут находиться в выбранном им месте; они не задают TARGET.

## Применение проверенных изменений

Из checkout обвязки выполнить:

```sh
"$PYTHON" -I -B tools/apply_offline_patch.py --source "$SOURCE"
```

Инструмент сверяет SHA256 патча и каждого изменяемого исходного файла, сначала
проверяет применимость, затем применяет изменения без записи в Git index и
проверяет SHA256 результата. Он ничего не скачивает. Изменённый исходник или
уже применённый патч блокирует повторное применение; использовать новый SOURCE.
Нулевой контекст diff допустим только вместе с этими проверками точных файлов.

## Сборка без доступа к сети

В подготовленном SOURCE настроить локальную замену Cargo registry/Git источников
на vendor. Использовать изоляцию сети на машине сборки; `--offline` не заменяет
изоляцию скриптов сборки. Не менять системные политики ради запуска.

Указать выбранные PATH/CARGO_HOME, существующие каталоги cache/vendor,
`CARGO_TARGET_DIR`, `CARGO_TARGET_X86_64_UNKNOWN_LINUX_MUSL_LINKER` и
`CC_x86_64_unknown_linux_musl`. Внутри изоляции из SOURCE:

```sh
export CARGO_NET_OFFLINE=true
export NPM_CONFIG_OFFLINE=true
export NPM_CONFIG_UPDATE_NOTIFIER=false
npm run build
cargo build --offline --locked --release -p silverbullet \
  --target x86_64-unknown-linux-musl
```

Никакие package-manager hooks не запускаются на сервере установки. На машине
сборки выполняются только проверенные скрипты закреплённых исходников.
Версия и timestamp ресурсов зафиксированы патчем; remap-path-prefix при
компиляции скрывает выбранные пути сборочной машины. В публичном отчёте
указывать параметры с обозначениями каталогов, не их фактическими значениями.

Проверить статическую линковку и фактический SHA256 бинарника. При отличии от
опубликованного manifest это другая сборка: не подменять старый архив/тег.
Повторить проверки из OFFLINE-AUDIT.md, проверить лицензии и назначить новую
supply_revision. Только после этого обновлять binary_sha256 и упаковывать по
RELEASING.md. Архив обвязки воспроизводим для одного и того же входного бинарника;
побайтная воспроизводимость компиляции Rust на другом инструментарии не заявлена.
