# Second Brain через отдельного сабагента

Поставка **second-brain-20261117**; серверное ядро offline.3 сохранено.

Рабочее правило этой поставки: основной агент поручает работу с Second Brain
сабагенту **secondbrain**. Сабагент сам читает серверные правила, выбирает
нужные навыки, ищет и правит записи. Основному агенту возвращаются краткий
результат, ссылки, подтверждённые изменения и вопросы.

Это настройка клиента, а не новый процесс внутри SilverBullet. Сервер не создаёт
сабагентов и не запускает модель. Мост и личный токен остаются теми же, что в
[SSH-MCP.md](SSH-MCP.md). Имя сабагента не меняет серверного пользователя:
авторизация и атрибуция определяются личным токеном сотрудника.

## Что остаётся в основном контексте

Основному агенту достаточно имени/краткого описания роли и правила делегирования
ниже. Не добавляйте серверные навыки, полный шаблон роли и содержимое страниц
в глобальный системный промпт, AGENTS.md или каждый запрос основного агента.
Профиль роли загружает среда при запуске сабагента. Сам сабагент читает через
MCP общие правила и только нужные процедуры; все навыки заранее не загружаются.

Скопируйте в действующие инструкции основного агента этот короткий блок,
сохранив остальные организационные правила:

```text
Работу с Second Brain передавай сабагенту secondbrain. Передай ему цель,
пространство (если известно), необходимые материалы, разрешённые изменения
и критерий готовности. Он сам читает правила и навыки через MCP. Получай от
него краткий результат со ссылками и подтверждёнными изменениями; полные
страницы и тексты навыков в основной контекст не загружай без необходимости.
Не расширяй поручение пользователя при делегировании. Если сабагент или его
MCP недоступен, сообщи причину; автоматически выполнять работу с базой в
основном контексте или обходить доступ другим транспортом не следует.
```

Инструкция уменьшает попадание прочитанных материалов и промежуточных вызовов
в основной диалог. Полное исключение описаний MCP-инструментов зависит от
клиента и его фильтрации инструментов. Если сервер включён глобально, его
описания могут добавляться раньше выбора роли. Нужны оба шага: отдельный
контекст сабагента и доступ к инструментам Second Brain только у этой роли.
Это не обещание нулевого расхода контекста и не новая серверная граница прав.

## OpenCode 1.19.5: готовый профиль

В поставке есть [agents/secondbrain.md](agents/secondbrain.md) — Markdown-профиль
V1 с `mode: subagent`, коротким описанием, инструментами и рабочим промптом.
Модель и провайдер не зафиксированы: действуют настройки вашей среды.

1. Сначала выполните личный `client.py login` и настройте локальный MCP с именем
   `secondbrain` по SSH-MCP.md. MCP включён, но не выдаётся основной роли.
2. В выбранном проекте создайте `.opencode/agents/`, если каталога нет.
   Скопируйте туда `agents/secondbrain.md`. Существующую роль не перезаписывайте:
   сравните и объедините изменения. Это файл на компьютере агента, не страница
   `Library/` и не установка модели/плагина.
3. В существующий config V1 добавьте фрагмент
   [agents/opencode-routing.example.json](agents/opencode-routing.example.json):

   ```json
   {"tools": {"secondbrain_*": false}}
   ```

   Это фрагмент для объединения с config, а не его замена. Профиль сабагента
   явно включает только нужные инструменты Second Brain. Если имя MCP другое,
   согласованно замените префикс в config и профиле роли. Не смешивайте синтаксис
   V1 с V2 (`agents`, `permissions`, `system`).
4. Добавьте короткий блок делегирования в уже действующие инструкции основной
   роли/проекта. Не включайте целый agents/secondbrain.md в общий AGENTS.md.
   Если политика ограничивает вызов сабагентов через Task, она должна разрешать
   основному агенту вызов роли secondbrain. Корпоративные запреты имеют приоритет;
   не снимайте их автоматически ради шаблона. Обязательные зеркала истории и
   снапшоты config обновляются по правилам вашей установки.
5. Перезапустите клиент/сессию, проверьте `opencode agent list`: роль secondbrain
   должна определяться как subagent. Затем поручите основному агенту маленький
   поиск через эту роль. До рабочего использования проверьте, что основной
   агент не вызывает Second Brain напрямую, а сабагент получает `help`/`read`.

В профиле отключены прочие инструменты, включая shell, веб, локальные файлы,
вложенные сабагенты, Lua и восстановление истории. Сохранение/правка доступны
технически, но применяются только при поручении. Git-снимок требует учёта того,
что он сохраняет всё пространство. Для роли, работающей только на чтение, дополнительно уберите
write/edit/git_commit из клиентского профиля. Это клиентское ограничение:
данный SSH MCP пока перечисляет только пространства с доступом write;
серверная поддержка отдельного MCP RO-токена здесь не добавлена.

Формат V1 и переопределение инструментов агентом описаны в
[OpenCode Agents](https://opencode.ai/docs/agents/), различия версий — в
[Migrate from V1](https://opencode.ai/docs/migrate-v1). Эти страницы могут
описывать более новый клиент; примеры этой поставки предназначены для V1.
Настоящую передачу контекста и фильтрацию MCP нужно принять на вашей сборке.

## GigaCode 26.10.104

Подключение MCP по stdio описано в SSH-MCP.md. Предоставленная справка GigaCode
описывает управление MCP, но не формат профиля сабагента. Поэтому эта поставка
не выдумывает команды `gigacode agent ...` или неизвестный конфигурационный ключ.

В доступной функции создания пользовательской роли/сабагента заведите роль
`secondbrain`. В качестве системной инструкции используйте тело
agents/secondbrain.md **после закрывающего YAML `---`**; YAML относится к OpenCode.
Описание возьмите из поля description. Подключите к роли MCP secondbrain,
оставьте только перечисленные в профиле инструменты и разрешите основной роли
делегирование. Серверные правила и навыки в главный промпт не копируйте.

Механизм создания роли и разделения контекстов нужно сверить с установленной
справкой/интерфейсом закрытого клиента. Допустимо прочитать `gigacode --help`
и справку только тех подкоманд, которые он действительно перечисляет.
Не устанавливайте обновления/плагины и не меняйте политики доступа ради профиля.
Если эта сборка не умеет изолированные сабагенты или инструменты по ролям,
зафиксируйте ограничение: настройку нельзя объявить успешно завершённой.
Отдельная независимая сессия со сведённым вручную ответом возможна только как
явно выбранный пользователем режим, она не создаёт автоматическое делегирование.

## Контракт задания и ответа

Пример короткого задания от основного агента:

```text
Цель: найти актуальный порядок выдачи доступа к сервису.
Пространство: указанное пользователем пространство.
Материалы: название сервиса и известные ссылки.
Изменения: чтение; ничего не сохранять.
Готовность: краткие шаги, источники и выявленные противоречия.
```

Для записи укажите, что именно пользователь поручил сохранить/исправить, границы
правки и нужен ли Git-снимок. Не передавайте всю переписку и секреты. Один вызов
сабагента соответствует связной задаче; уточнения одной задачи можно направлять
в его продолжаемый контекст, если клиент это поддерживает. Не запускайте по
сабагенту на каждую ссылку и несколько писателей одной страницы без необходимости.

Ответ по умолчанию — до 200 слов: результат, ссылки с указанием пространства,
подтверждённые изменения/ревизии, проверка и нерешённый вопрос. При необходимости
большой материал сохраняется в согласованную страницу; основной агент получает
ссылку. Пользователь может явно запросить полный текст или нужную цитату.

Задачи из SilverBullet передаются так же, но этот профиль работает с записями,
а выполнение кода/команд остаётся основному исполнителю. Постоянный task-worker,
расписание и распределённая очередь этим профилем не устанавливаются.

## Приёмка на рабочем месте

1. Роль secondbrain существует в клиенте, имеет отдельную историю сообщений
   и доступ к нужному MCP. У основной роли прямые инструменты базы скрыты.
2. Основной агент делегирует тестовый поиск. В журнале сабагента видны help,
   правила, нужный навык и чтение источника. В основном диалоге остаётся итог,
   без тел навыков и полной страницы.
3. При отдельном разрешённом тесте записи сабагент сохраняет одну тестовую
   страницу, проверяет её повторным read и возвращает ссылку/ревизию. Рабочие
   страницы для пробы не меняются. Snapshot проверяют, только если он поручен.
4. Ошибка доступа возвращается основному агенту без попыток читать секреты,
   включить shell/Runtime или обойти MCP прямыми запросами.

Установка профиля не переписывает серверные навыки. Если они уже импортированы,
обновлять приложение, перезапускать сервер или переносить мост для этого не
нужно. Новый сервер/личные токены требуются только для перехода со старого ядра
без SSH MCP — см. SSH-MCP.md.
