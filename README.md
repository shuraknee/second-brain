# Second Brain — офлайн SilverBullet

Веб-интерфейс заметок и встроенный MCP для агентов. Поставка не скачивает файлы
при запуске; исходящие соединения сервера запрещены. Общие требования:
**Linux x86_64, Python >=3.9, systemd --user, libseccomp и strace**.

Поставка универсальная: в ней нет профиля конкретной организации/сервера,
его адресов, имени пользователя, выбранных каталогов или конфигурации установки.
Параметры появляются только в локальном плане и config после выбора оператором.
Исходники SilverBullet и его проверенный бинарник не модифицируются.

Это независимая обвязка для [SilverBullet](https://github.com/silverbulletmd/silverbullet),
а не авторство его ядра. Наша обвязка — MIT (`LICENSE`); исходное авторство
SilverBullet сохранено в `LICENSE.silverbullet.md`. Другие лицензии, уведомления
и необходимые исходники компонентов включены в `licenses/`. См.
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) и [LICENSING.md](LICENSING.md).

## Быстрая установка через агента

Передайте агенту [agent.md](agent.md), скачанный архив и поручение:

> Установи Second Brain по agent.md в указанный мной абсолютный каталог.
> Уточни только недостающие порты, публичный URL и другие обязательные параметры.
> Проверь SHA, окружение и сетевую изоляцию, подготовь и примени план в рамках
> моего поручения. Не скачивай зависимости, не используй sudo и не ослабляй защиту.

Укажите свой TARGET. Агенту не требуется менять пути в исходниках или вручную
редактировать systemd-шаблоны. Полные команды: [INSTALL.md](INSTALL.md).

## Получить готовые файлы

Во вкладке Releases текущего репозитория выберите **offline-licensed-20261110**.
Скачайте `silverbullet-linux-x86_64-py39-offline-licensed-20261110.tar.gz` и одноимённый
`.sha256`. Инструкции agent.md и INSTALL.md приложены отдельно.
Получение файлов выполняется заранее через разрешённый браузер/канал.

После проверки SHA и распаковки отдельно от TARGET:

```sh
"$PYTHON" -I -B "$SOURCE/tools/install.py" plan \
  --target "$TARGET" --port "$PORT" --backend-port "$BACKEND_PORT" \
  --public-url "$PUBLIC_URL" --admin-user "$ADMIN_USER" --output "$PLAN"
"$PYTHON" -I -B "$SOURCE/tools/install.py" apply --plan "$PLAN" --sha256 "$PLAN_SHA256"
"$PYTHON" -I -B "$TARGET/tools/install.py" status --target "$TARGET"
```

Значения переменных выбираются по INSTALL.md. Plan проверяет payload, порт,
пустой TARGET и реальную временную user-службу с изолированной сетью. Apply
перепроверяет план и файлы, копирует поставку в выбранный каталог и создаёт
только новые user-unit. Чужие службы и существующие данные не заменяются.

Пробелы, кириллица, `%` и `$` в TARGET поддерживаются. Для длинного TARGET
Unix-сокет получает отдельный короткий путь в XDG_RUNTIME_DIR; доступен явный
`--runtime-dir`. Стандартные `/proc` и XDG — инфраструктура ОС, не путь проекта.

## Обезличивание

В runtime-архиве только фиксированный набор файлов: бинарник, обвязка,
незаполненный пример config, инструкции, шаблоны, лицензия и контрольные суммы.
Лицензионные уведомления и исходники отдельных сторонних компонентов входят
в поставку для соблюдения их условий распространения.
Тесты, отчёты/трассы разработки, диагностика хоста, UID/GID владельца сборки,
имена пользователей и времена исходных файлов в поставку не включаются.
Владельцы и времена tar/gzip нормализованы. Происхождение и SHA256 продукта
сохранены в [manifest.json](manifest.json): это сведения о ПО, не об установке.

Данные, пароли, токены, private configs, планы и фактический inventory
генерируются только локально и не публикуются. collect_environment.py читает
сведения о системе только по явному запуску оператором; готовых сведений внутри нет.
Его JSON нужен для локальной диагностики и не должен попадать в git/assets.

## Статус и ограничения

Поставка — **кандидат до приёмки на выбранном сервере**. Встроенный MCP
экспериментальный. Установленные системные инструменты проверяются до установки;
pip, Chromium и скачивания при старте не нужны. Поддержка изоляции зависит от
ядра и политик ОС: при отказе preflight установка останавливается без обхода.

Перед рабочим использованием проверить вход, заметки, OAuth/MCP, перезапуск,
внешний HTTPS и сетевые ограничения именно на целевом сервере. Автообновление
существующей установки и миграция не реализованы. SSH, SELinux/AppArmor,
firewall и linger установщик не меняет.

## Сборка из исходников

Git checkout содержит инструменты сборки и синтетические тесты. Runtime-архив
не содержит тестовых исходников или отчётов. Для сборки из checkout используется
уже скачанный проверенный бинарник:

```sh
"$PYTHON" -I -B tools/build_supply.py --binary "$BINARY" --output "$ARCHIVE"
```

Оба пути задаются явно; каталог вывода уже должен существовать. В сборке нет
привязки к диску, UUID или каталогу разработчика. Бинарник хранится в Release
Assets, его SHA проверяется при сборке и запуске. Включённые в тесты IP/порты
являются синтетическими фикстурами, loopback или адресами из документационных
диапазонов, а не параметрами чьего-либо сервера.
